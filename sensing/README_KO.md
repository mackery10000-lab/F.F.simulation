> **현재 입력:** `video_api_refresh_r2`. 원본 영상 전체를 MediaPipe Heavy로 새로 추론하고, API 60회·2 Hz·360프레임의 실제 좌표 추론을 결합한 25 FPS·4,500프레임·23관절 모션입니다. 이전 활성 모션 대비 84프레임의 336개 좌표 값이 바뀌었습니다. [현재 모델 실행 보고서](../reports/video_api_refresh_r2/REPORT_KO.md)를 참조하세요. `metric_valid=false`와 관측 신뢰도를 보존하며 전체 정확도 향상을 주장하지 않습니다. 센싱은 API를 호출하지 않고 완성된 숫자 모션을 읽습니다.

> `/api/sensing-motion`은 공통 모션·렌더링 자산의 해시와 시간축을 검사합니다. LUNA 합성 장면은 회귀 검증용이며 기본 입력이 아닙니다. 선수 ID는 RF 차폐와 독립이고, 거리·태그 카드는 관측/필터/예측/만료 상태를 공유합니다.

**페레이라(A)·션 스트릭랜드(B)의 가상 경기에서 센서 작동을 확인하는 전용 화면**입니다. 메인 관제·카메라·ISAC·UWB·손목 IMU·최종 분석의 여섯 화면에서 센서 관측과 분석 결과가 같은 시간에 갱신됩니다. 경기장은 센서의 위치와 관측 범위를 확인하는 환경이며, 센싱 화면에는 원본 영상 플레이어와 3D 제작 설명·메뉴를 표시하지 않습니다.

## 실행

루트 `RUN_SENSING_WINDOWS.bat` → **http://127.0.0.1:5186/#/sensing**.

기존 분석 스튜디오가 실행 중이면 ‘멀티센서 랩’을 선택합니다. 화면을 열면 선수 A/B·기술·관측창·시간 조건으로 집중 분석 질문을 선택합니다. **질문을 적용하고 경기 시작**을 눌러야 센싱이 시작되며 질문 없이도 시작할 수 있습니다. 재생·일시정지·배속·시간 이동은 여섯 화면에서 공유됩니다. 환경 연결에 실패하면 오류와 재연결 버튼을 표시합니다. Python 코칭 서버나 외부 AI 연결은 필요하지 않습니다.

## ‘실시간’의 의미

저장된 3D 모션을 시간에 맞춰 재생하면서 **해당 프레임까지의 센서 샘플만 생성·수신·분석하는 실시간 시뮬레이션**입니다. 실물 센서나 생중계의 실측값을 수신하는 기능은 아닙니다.

- `MeasurementSampler`: 장치별 샘플 커서·난수 상태를 유지하며 현재 경기 시각까지 샘플을 생성합니다.
- `LiveSensingSession`: 수신 지연이 끝난 패킷만 융합 입력에 넘깁니다. 후보가 닫히고 시간창이 지난 뒤 시도 이벤트를 확정합니다.
- `live-worker.ts`: 메인 화면과 분리한 Web Worker에서 관측과 분석을 수행합니다.
- 그래프에는 최근 8초의 관측을 보내고, 전체 경과 관측은 worker에 보관합니다. 미래 경기 전체를 미리 계산해 그래프처럼 재생하지 않습니다.
- 뒤로 이동하면 이후 기록을 버리고 같은 시드와 원본 모션으로 해당 시각까지 재구성합니다. 앞 이동도 완료 이벤트를 누락하지 않도록 짧은 구간으로 처리합니다.
- 비동기 응답에 세대 번호를 붙여 이전 재생 응답이 새 시간 이동 결과를 덮어쓰지 못하게 합니다.
- 원시 관측은 `simulation_flag: true`, `source_type: simulated_sensor`, `input_mode: synthetic` (레거시는 video_derived)로 표시합니다.

## 개발 참고: 입력·좌표 보존

기본 입력은 기존 표시용 `fighter_A.glb`, `fighter_B.glb`와 새 23관절·4,500프레임·25 FPS 합성 모션입니다. 아래 내용은 개발·검증 참고이며 센서 관제 UI에는 표시하지 않습니다.

`data/octagon_approx.obj`와 `scene.json`은 기존 근사 옥타곤이며 정적 그룹으로 로드합니다. 선수는 기존 GLB와 같은 bone-target retarget 방식을 사용해 기존 관절 좌표에 맞춰 재생합니다. 센서 오버레이는 별도 그룹입니다. 정적 경기장과 표시용 mesh를 유지하며, 새 합성 관절 좌표를 동일한 렌더러와 센싱에 전달합니다. 원본 영상 추적·재구성 결과는 백업/레지스트리에 보존합니다.

원본 V9의 A/B 슬롯은 **A=Alex Pereira, B=Sean Strickland**입니다. 화면 좌우나 가까운 센서에 따라 ID를 교환하지 않습니다. 카메라 수집을 꺼도 원본 모델을 센서 추정 좌표로 대체하지 않습니다.

## 측정·분석 모델과 제한

카메라는 실제 관절 포즈에 가림·FOV·잡음을 적용한 합성 관측이며, 관절을 카메라 평면에 투영합니다. 실제 9대 영상이나 픽셀 기반 자세 추정을 수행하지는 않습니다.

ISAC은 5.8 GHz·16 부반송파·2×2 안테나 링크의 산란 경로로 복소 CSI를 합성합니다. 수신 CSI에 Hann 32샘플 STFT를 적용합니다. 도플러·움직임 특징은 시간 보완 근거이며, 손목 위치·펀치 종류·적중을 단독 판정하지 않습니다. RF 파동은 설명용 그래픽입니다.

UWB는 DS-TWR 범위 관측으로 고정 높이 2D 측위를 수행합니다. 알려진 위치의 고정 앵커 4개와 허리 이동형 태그 2개를 사용합니다. NLOS·잡음·기하 조건·유효 앵커 부족·관측 만료를 반영합니다. 허리 거리는 주먹–얼굴 거리와 다릅니다.

IMU는 기존 손목 위치의 후방 차분과 팔뚝 방향 변화에서 3축 가속도·각속도·jerk를 생성합니다. 같은 손목의 급가속과 카메라의 팔 궤적이 시간창 안에서 일치하면 시도로 연결합니다. 실험적 규칙 분류이며 적중, 실제 충격력(N), 학습된 분류 정확도를 제공하지 않습니다.

현재 합성 3D와 기존 단안 3D 모두 미터 보정된 실측 좌표가 아닙니다. 거리·가속도에는 **표시 단위**를 사용하며, ToF·도플러는 표시 좌표에 길이 스케일을 가정한 합성 모델 특징입니다. 영상 가림·신원 불확실·두 선수의 큰 겹침에서는 식별 신뢰도를 낮추고 판정을 보류합니다. 2차 분석은 충분한 독립 반복에만 근거·표본 수를 제시합니다.

## 입력 무결성 연결

`/api/sensing-motion`이 저장된 gzip 및 계약·코드 해시와 시간축·A/B 슬롯을 검증합니다. 원본 영상 파일은 런타임 의존성이 아닙니다. 이전의 Windows CRLF 체크아웃과 LF manifest 해시 차이는 **텍스트의 CRLF→LF 정규화 해시만 추가 허용**하도록 해결했습니다. 실제 내용이 바뀐 입력, 잘못된 SHA, 바이너리 3D·영상·모션 변경은 계속 거부합니다. 원본 파일이나 V9 결과를 다시 쓰지 않습니다.

## 저장·검증

최종 분석 탭의 선택형 질문은 경기 중 집중 답변·경기 후 집중 최종 답변·경기 후 심층 답변의 세 영역과 연결됩니다. 경기 중·후 추가 심층 요청을 등록할 수 있습니다. 질문·계산값·원본 이벤트·거리 시계열을 IndexedDB에 저장하고 새로고침 후 ‘저장된 분석 보기’로 복원합니다. 종료된 분석은 근거 시점 재생이나 센서 재샘플링으로 덮어쓰지 않습니다. [질문 목록·24개 후보 평가·실제 검증](../reports/tactical_questions/REPORT_KO.md).

최종 분석의 ‘현재 분석 DB 저장’은 경과 이벤트·거리·패턴 근거를 IndexedDB에 저장합니다. ‘실시간 리포트’는 현재 시각까지 worker에 축적된 전체 관측과 분석을 JSON으로 내보냅니다. 저장본은 현재 브라우저·포트 범위이며, 명중·과거 경기 데이터를 새로 만들어내지 않습니다.
