# FIGHT FREQUENCY · MMA Sensing

원본 영상을 새로 분석해 재구성한 두 선수의 관절 모션을 입력으로 사용하는 차세대 무선통신·멀티센서 센싱 시뮬레이션입니다. 카메라, ISAC, UWB, 손목 IMU의 관측·지연·누락·시간 동기화·융합 과정을 비교하고, 경기 중/후 전술 질문을 근거 이벤트와 함께 분석합니다.

실제 Wi-Fi CSI 수집, 무선 장비 연결, 실측 정확도 평가를 수행하는 시스템은 아닙니다. 좌표는 단안 영상 기반 비보정 2.5D 추정이며, 거리·속도·가속도는 시뮬레이션 표시 단위입니다. 적중, 실제 충격력, 선수의 의도와 하드웨어 성능을 확정하지 않습니다.

## 설치와 실행

Node.js **22.18 이상**과 최신 Edge/Chrome, WebGL, 약 1 GB의 여유 디스크 공간이 필요합니다. Python, 영상 파일, AI 모델, API 키, 유료 서비스는 필요하지 않습니다. 최초 의존성 설치에는 인터넷이 필요하며, 설치 후 로컬 실행은 외부 서비스에 접속하지 않습니다.

Windows는 `RUN_WINDOWS.bat`을 실행합니다. 또는 이 폴더에서:

```sh
npm ci
npm test
npm run build
npm start
```

브라우저에서 **http://127.0.0.1:3000/#/sensing** 을 엽니다. 종료는 터미널에서 Ctrl+C입니다. 포트가 사용 중이면 `npm start -- --port 5190 --strictPort`로 실행하고 출력된 주소에 접속합니다. 브라우저 저장은 해당 주소와 포트에 귀속됩니다.

개발 중에는 `npm run dev`, 정적 검사는 `npm run check`를 사용합니다. `dist` 폴더만 정적 호스팅하면 모션 API가 없어 실행되지 않습니다. `npm start`가 제공하는 로컬 입력 API와 함께 실행해야 합니다.

## 사용 방법과 유지된 설정

1. 경기 전 창에서 선수 A(페레이라)/B(스트릭랜드), 분석 분야, 기준 펀치, 분석 구간과 후속 관측창을 선택해 질문을 등록합니다. 질문 없이 경기 시작도 가능합니다.
2. 여섯 탭에서 메인 관제, 카메라, ISAC, UWB, 손목 IMU, 최종 분석을 확인합니다.
3. 재생·일시정지·처음으로·0.5/1/2/4배속과 0~179.96초 타임라인(0.04초 간격)을 조작합니다.
4. 수집 설정에서 네 종류의 센서를 각각 켜거나 끕니다. 표시 레이어와 데이터 수집은 별개입니다. 기존 9개 카메라 선택, FOV, 센서 선택, 선수 추적 확대, 천장/초기 시점, 드래그 회전과 휠 확대를 제공합니다.
5. 최종 분석에서 경기 중 집중 답변, 경기 후 집중 최종 답변, 경기 후 심층 답변을 구분합니다. 질문 수정·삭제, 손·선수·시간·거리 조건, 근거 재생, JSON 리포트와 DB 저장을 지원합니다. 기존 항목의 범위·기본값·계산 연결을 유지했습니다.
6. 질문·답변·수신 분석은 IndexedDB에 자동 저장됩니다. 새로고침 후 저장된 분석 보기로 복원합니다. 시크릿 모드나 브라우저 데이터 삭제 시 저장 내용이 없어질 수 있습니다. 다른 포트의 기존 기록은 공유되지 않습니다.

센서 기본 수집률은 카메라 30 Hz / ISAC 64 Hz / UWB 20 Hz / IMU 100 Hz입니다. 센서의 지연·누락·노이즈·동기화·융합 파라미터는 기존 `sensing/sensors.ts`의 값과 그대로 연결됩니다. UI가 노출하지 않는 새 조절 항목을 추가하지 않았습니다. 노이즈와 규칙에 따른 신뢰도는 학습된 분류 정확도나 성공 확률이 아닙니다.

## 입력과 처리 구조

`assets/sensing/motion.json.gz`는 원본 180초 전체를 MediaPipe Heavy로 새로 추론한 25 FPS · 4,500프레임 · 23관절 · 선수 A/B의 Z-up 모션입니다. 같은 좌표로 렌더링한 `assets/sensing/3d_capture.mp4`를 센싱 화면에서 재생할 수 있습니다. 관측 없는 관절은 판정 근거에서 제외합니다. 깊이·스케일·선수 식별은 독립 실측 검증되지 않았습니다.

```text
완료된 모션 + 입력 무결성 manifest
  → 공통 시간 샘플러 endpoint_ik_v2
      → 기존 리타기팅 → minimal_shell_v1 GLB 표시
      → 기존 센서 어댑터 → 센서 모사 → 시간 동기화·융합
          → 이벤트·거리 → 전술 질문 → 브라우저 저장/JSON
```

렌더러와 센싱은 동일한 모션과 시간 샘플러를 사용합니다. 새로 추론한 관절 궤적을 사용하며 프레임 사이 자세는 미관측 보간입니다. 센싱 결과는 모델 생성에 피드백되지 않습니다. `assets/sensing/manifest.json`의 SHA-256으로 모션·장면·GLB·샘플러를 검사하며, 변조 시 명시적으로 실패합니다. 모션을 임의 편집한 뒤 manifest를 그대로 두면 로드되지 않습니다.

## 폴더 구조

```text
app/                 센싱 전용 진입점, 기존 여섯 화면, 스타일, 입력 API, Vite 설정
sensing/             기존 센서·융합·전술·저장 및 worker 모듈
motion/              렌더러와 센싱이 공유하는 시간 샘플러
data/                옥타곤 장면과 정적 참조 OBJ
assets/sensing/      완료된 좌표 gzip 및 해시 manifest
assets/fighters/     실제 사용하는 minimal_shell_v1 GLB 두 개와 manifest
assets/fonts/        Paperlogy 400/500/600/700 및 OFL
vendor/three/        필요한 Three.js 런타임과 로더·컨트롤
tests/               패키지 입력·실제 센싱·손상 거부 검사
package*.json        고정 의존성과 설치 명령
PACKAGE_MANIFEST.json 소스·에셋 파일 목록과 해시
RUN_WINDOWS.bat      설치 확인 → 빌드 → 로컬 실행
```

원본 영상·추적/3D 생성 프로그램·Blender·AI 가중치·개발 가상환경·캐시·환경 키·무관한 실험/영상 분석 화면은 포함하지 않습니다. 실제 센싱에서 사용하는 기존 기능은 동일한 소스 모듈로 유지합니다. 별도의 클라우드 백엔드는 없으며 로컬 Vite API는 검증된 입력을 읽기 전용으로 제공합니다.

## 디자인과 글꼴

사용자 제공 FM26 포털·선수단·전술·경기일 참고 화면의 남색 배경, 보라색 강조, 패널 구획과 표 행 구분을 적용했습니다. 게임 스크린샷·로고는 포함하지 않습니다. Paperlogy 원본 TTF를 본문 400, 컨트롤·수치 500, 제목·버튼 600, 메인 제목 700에 매핑했습니다. DOM·SVG·Canvas 센서 라벨까지 적용하며, 미지원 특수 기호만 운영체제 기호 글꼴로 대체합니다. 저작권과 라이선스는 `THIRD_PARTY_NOTICES.md`를 참조하세요.

## 검증과 제약

`npm test`는 패키지에 포함된 실제 좌표가 센서 측정으로 연결되는지, A/B·시간축이 맞는지, 손상된 입력을 거부하는지 검사합니다. Git의 텍스트 CRLF↔LF 체크아웃은 같은 내용으로 검증하고 다른 텍스트 변경과 바이너리 변경은 거부합니다. 원본 개발 프로젝트에서는 기존 103개 회귀 검사, UI 변경 전후 전체 경기 관측·이벤트·거리 해시 비교와 실제 Edge 브라우저 기능 검사를 수행했습니다. 관측 모사는 실제 무선 계측 또는 임상/경기 판정용 정확도 검증을 대체하지 않습니다.

이 폴더 내부만 별도 저장소로 업로드할 수 있습니다. 생성된 `node_modules/`, `dist/`, 개인 `.env`는 업로드하지 않습니다. 원격 푸시와 공개 배포는 수행하지 않았습니다.

## MMA motion-v2 업그레이드 · 원본 영상 기준 교체

현재 기본 입력은 **새 원본 영상 재구성 모션**입니다. 이전 LUNA 합성 모션은 회귀 시나리오로만 남아 있으며 기본 센싱 입력이 아닙니다. 23관절, 25 FPS, 4,500프레임, 179.96초, A/B 슬롯, metric_valid=false입니다. 새 180초 3D MP4·관절 GLB와 수치 모션의 해시를 연결했습니다.

`npm run build`, `npm test`, `npm run replay`, `npm run replay:scenes`로 독립 검증할 수 있습니다. 시뮬레이션에는 Python/키/외부 API가 필요 없습니다. 파생 3D 영상만 포함하며 원본 경기 영상·환경변수·키·모델 가중치·Blender 실행파일·node_modules는 배포하지 않습니다.

[이번 교체 실행 보고서](reports/video_3d_replacement/REPORT_KO.md), [이전 합성 생성 보고서](reports/mma_3d_sensing_upgrade/REPORT_KO.md), [MMA 분류·제한](docs/MMA_MOVEMENT_TAXONOMY_KO.md). 로컬 동기화와 외부 GitHub push는 별개이며 이 작업에서 push하지 않았습니다.

## 영상 API 검토 및 센싱 신뢰성 보완

현재 모션은 외부 API의 180개 영상 프레임 검토 후 제한적 관절 보정을 적용한 버전입니다. 전체 3D 정확도 향상은 입증되지 않았습니다. 관측/필터/예측/만료를 구분하고 ID 신뢰도와 UWB 차폐를 분리했습니다. [최신 실행 보고서](reports/autonomous_execution/REPORT_KO.md)에 오차 증가를 포함한 비교와 검증 결과가 있습니다.
